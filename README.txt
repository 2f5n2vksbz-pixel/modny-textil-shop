МОДНЫЙ ТЕКСТИЛЬ — версия для публикации на Render

СОДЕРЖИМОЕ
- index.html — витрина, каталог, корзина и форма заказа.
- server.js — сервер принимает заказы и отправляет их через Telegram Bot API.
- package.json — зависимости и команда запуска.
- render.yaml — конфигурация Render.

ПУБЛИКАЦИЯ
1. Загрузите все четыре файла в корень GitHub-репозитория modny-textil-shop.
2. В Render выберите New > Blueprint и подключите этот GitHub-репозиторий.
3. Render прочитает render.yaml. Создайте Web Service.
4. В Environment добавьте:
   BOT_TOKEN = токен бота из BotFather (секрет, никому не отправлять)
   MANAGER_CHAT_ID = числовой Telegram chat_id менеджера @gurban95
5. Нажмите Deploy. Проверка сервера: https://ВАШ-САЙТ/health должна вернуть {"ok":true,...}.

ВАЖНО ПРО MANAGER_CHAT_ID
Telegram Bot API отправляет личные сообщения по числовому chat_id. Одного @username недостаточно.
Менеджер должен открыть https://t.me/ModnyTextilOrdersBot и нажать Start, иначе бот не сможет написать ему первым.
Затем нужно безопасно получить числовой chat_id менеджера через Telegram getUpdates с токеном бота и внести его в MANAGER_CHAT_ID в Render. Не публикуйте токен в GitHub, переписке, скриншотах или исходном коде.
Если getUpdates показывает пустой список, сначала отправьте боту /start от аккаунта менеджера и повторите запрос.
Никогда не добавляйте .env с токеном в GitHub.

ПРОВЕРКА
После настройки отправьте тестовый заказ с сайта. Успешная отправка означает, что менеджер получил сообщение в Telegram.
Пока BOT_TOKEN и MANAGER_CHAT_ID не добавлены, форма не сможет отправлять заказы.

ПРИМЕЧАНИЯ
- В каталоге пока временные иллюстрации и цены «уточняются»; замените их на подтверждённые фото и цены до запуска рекламы.
- Бесплатный Render может останавливать сервис после периода бездействия; для магазина, который должен принимать заказы круглосуточно, выберите постоянно работающий тариф.
